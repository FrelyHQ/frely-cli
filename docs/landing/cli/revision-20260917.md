## 项目定位分析（方向 A 已确认）

**项目层定位建议：Frely 的开源连接客户端。**

它连接的是几条方向不同的路径，而不只是把三个功能放进一个 CLI：

| 路径 | 受众与任务假设 | 当前证据与首页角色建议 |
| --- | --- | --- |
| 云端 AI → 本机工具 | 已使用远程 AI、愿意运行 CLI，希望 AI 处理电脑中的文件、命令和持续进程的用户 | 已发布命令、任务具体；建议作为当前首页主入口 |
| 本机模型 → Frely | 已运行 Ollama/兼容运行时，并希望通过 Frely 接入点使用该模型的现有用户 | 已发布命令，但有模型、Provider 槽位和平台使用背景门槛；建议作为第二场景 |
| 现有 AI 客户端 → 远程 Agent | 希望继续使用当前客户端与模型配置，同时调用 Frely 托管 Agent 的用户 | 源码可见实现但核验发行包不支持；当前仅介绍开发方向 |
| Network 接入 | 有独立钱包/Network 能力使用任务的用户 | 与以上三条路径的目的和认证不同；是否在独立文档入口展示待确认，首页本轮未扩展 |

“开源”支持审查客户端代码和本机执行边界；云端连接需要 Frely 服务。不能把开源许可当作完全离线、整个平台开源、自动沙箱或永远免费的证据。

**已确认的首页方向：吸引希望远程 AI 使用本机工具的新用户，并帮助他们开始连接。**

用户补充：“安装&使用要想现在一样，比较靠前……还有一个主站 frely 引流，进来的用户可能首要目标是安装 cli，而不是看它能做什么。”

据此保留两条阅读路径：新访客从首屏了解用途后开始安装；主站导流访客直接使用首屏命令或 #install 入口。安装、登录与使用指引排在详细功能说明前。

理由是发布能力、可解释的用户问题和可验收结果更一致。这是基于产品实现的设计判断；尚无访谈证明该人群是最大市场，也无转化数据证明比另两条路径更好。
